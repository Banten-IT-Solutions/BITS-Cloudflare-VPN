## ✨ Features

| Feature                   | Description                                                                                                                               |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **VLESS Relay**           | VLESS over WebSocket.                                                                                                                     |
| **Four Frontend Pages**   | `/`, `/build`, `/country`, `/convert`.                                                                                                    |
| **Provider Build**        | Build config from proxy list with search, filter, and ping check.                                                                         |
| **Country Build**         | Build config by country path like `/ID` or `/ID,SG`.                                                                                      |
| **URI ↔ Clash Converter** | Convert VLESS URI to Clash YAML and back.                                                                                                 |
| **Proxy List API**        | Paginated proxy list with country, port, and query filters.                                                                               |
| **Country KV Source**     | Country buckets loaded from `KV.json` for relay routing.                                                                                  |
| **Latency Probe**         | `/api/check` validates allowed proxy target with rate limit.                                                                              |
| **Cloudflare Native**     | Workers, Assets, custom domain, and observability.                                                                                        |
| **Automated Data Sync**   | `proxy.txt`, `raw.txt`, and `KV.json` generated by helper scripts.                                                                        |
| **Dynamic Configuration** | Uses `wrangler.template.jsonc` + `bun run cf:config` to inject `${VAR}` from `.env` / GitHub Variables — no environment values committed. |
| **Code Quality**          | Prettier + `simple-git-hooks` + `lint-staged` — auto-format on commit, typecheck on push.                                                 |

## 🚀 Quick Start

### Prerequisites

- Node.js 20+ or [Bun 1+](https://bun.sh)
- [Cloudflare account](https://dash.cloudflare.com) with an active zone for your custom domain
- Wrangler CLI (`bun add -d wrangler`)

### 1. Clone

```bash
git clone https://github.com/Banten-IT-Solutions/BITS-VPN-Cloudflare.git
cd BITS-VPN-Cloudflare
```

### 2. Install

```bash
bun install
# → auto-installs git hooks via `prepare` (simple-git-hooks)
```

### 3. Configure (Local)

```bash
cp .env.example .env        # vars: WORKER_NAME, PRX_BANK_URL, KV_PRX_URL, APP_DOMAIN, WC_DOMAIN
cp .dev.vars.example .dev.vars  # secrets: SUB_TOKEN

# Edit .env — minimum required:
#   WORKER_NAME, PRX_BANK_URL, KV_PRX_URL, APP_DOMAIN, WC_DOMAIN

bun run cf:config           # validates REQUIRED vars and generates wrangler.jsonc (gitignored)
```

> `wrangler.jsonc` is generated and gitignored. It is the only config consumed by `wrangler dev` / `wrangler deploy`.

### 4. Develop

```bash
bun run dev     # otomatis cf:config → wrangler dev (local HMR)
```

### 5. Required Cloudflare Resources (One-Time Setup)

Create these **once** before the first deploy. CI only deploys code — it does not provision resources.

| Resource          | Command / Dashboard                                                                                                                                                         |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Custom Domain** | Ensure `APP_DOMAIN` and `WC_DOMAIN` belong to an active zone in your Cloudflare account. `wrangler deploy` auto-provisions them from `routes` in `wrangler.template.jsonc`. |
| **SUB_TOKEN**     | A random secret: `openssl rand -base64 48`                                                                                                                                  |

## ☁️ Deploy

Choose one method. **Local** for quick testing; **Remote (GitHub Actions)** for production / team workflows.

### 🖥️ Option A — Local Deploy (from your machine)

Best for development, testing, or one-off deploys. Uses your local `.env` + `.dev.vars` and your authenticated `wrangler` session.

```bash
npx wrangler login          # first time only
bun run cf:config
bun run deploy              # → wrangler deploy (uses generated wrangler.jsonc)
```

> **Use when:** you want fast iteration without GitHub. **Not ideal for:** shared production where secrets should live in CI.

---

### ☁️ Option B — Remote Deploy via GitHub Actions to Cloudflare (Recommended)

Production and team workflow. Code is built and deployed by GitHub Actions using **GitHub Variables + Secrets** — triggered manually via `workflow_dispatch`.

**Steps:**

1. Fill in **GitHub Variables** and **GitHub Secrets** (tables below) at `Settings → Secrets and variables → Actions`.
2. Go to GitHub → `Actions → Deploy → Run workflow`.
3. The workflow runs: `cf:config` → `typecheck` → `wrangler deploy` → `secret bulk`.

> Pushes to `main` do **not** auto-deploy — deployment is `workflow_dispatch` only. Validation is enforced by `scripts/gen-wrangler.mjs`; missing required variables will fail `bun run cf:config` with a clear error.

#### GitHub Variables

Non-sensitive. Configure at `Settings → Secrets and variables → Actions → Variables`. These fill `${VAR}` placeholders in `wrangler.template.jsonc` via `bun run cf:config`.

| Variable       | Example                                           | Required    | Description                                           |
| -------------- | ------------------------------------------------- | ----------- | ----------------------------------------------------- |
| `WORKER_NAME`  | `bits-vpn-cloudflare`                             | ✅ Required | Worker name on Cloudflare                             |
| `PRX_BANK_URL` | `https://raw.githubusercontent.com/.../proxy.txt` | ✅ Required | Remote proxy list source                              |
| `KV_PRX_URL`   | `https://raw.githubusercontent.com/.../KV.json`   | ✅ Required | Country bucket KV source                              |
| `APP_DOMAIN`   | `yuliana.my.id`                                   | ✅ Required | Main custom domain (must be an active zone)           |
| `WC_DOMAIN`    | `support.zoom.us.yuliana.my.id`                   | ✅ Required | Second custom domain (wildcard / SNI host)            |
| `APP_URL`      | `https://yuliana.my.id`                           | Optional    | Smoke-test target; defaults to `https://<APP_DOMAIN>` |

#### GitHub Secrets

Sensitive. Configure at `Settings → Secrets and variables → Actions → Secrets`. Injected via `wrangler secret bulk` during deploy. For local dev, put them in `.dev.vars`.

| Secret                  | Required    | Description                                       |
| ----------------------- | ----------- | ------------------------------------------------- |
| `CLOUDFLARE_API_TOKEN`  | ✅ Required | Cloudflare API token with Workers Edit permission |
| `CLOUDFLARE_ACCOUNT_ID` | ✅ Required | Cloudflare Account ID (Dashboard → right sidebar) |
| `SUB_TOKEN`             | ✅ Required | Token for `/api/sub` and derive UUID              |

### 6. Configuration Flow

No worker names, domains, proxy URLs, or tokens are committed. All values are injected at build time:

```
wrangler.template.jsonc  (committed, contains ${VAR} placeholders)
        │  bun run cf:config  (scripts/gen-wrangler.mjs)
        ▼
wrangler.jsonc           (generated, gitignored — used by wrangler)
        ▲
        ├─ local : .env + .dev.vars           →  Option A (Local Deploy)
        └─ CI    : GitHub Variables + Secrets →  Option B (Remote Deploy)
```

- `"${VAR}"` in template → replaced as a JSON string (quoted value).
- `${VAR}` in template (unquoted) → replaced as raw JSON (arrays / booleans / numbers).

## 💻 Development

### Commands

| Command                | Description                                                   |
| ---------------------- | ------------------------------------------------------------- |
| `bun run cf:config`    | Generate `wrangler.jsonc` from `.env` / environment           |
| `bun run dev`          | Start local Worker dev server (auto-runs `cf:config`)         |
| `bun run deploy`       | Deploy Worker to Cloudflare (auto-runs `cf:config`)           |
| `bun run build`        | Alias for `cf:config` (wrangler bundles the Worker at deploy) |
| `bun run types`        | TypeScript type-check (`tsc --noEmit`)                        |
| `bun run check`        | Alias for `bun run types`                                     |
| `bun run fetch.ts`     | Merge raw proxy sources into `raw.txt`                        |
| `bun run scan.ts`      | Scan active proxy and generate `proxy.txt` / `KV.json`        |
| `bun run format`       | Format all files with Prettier                                |
| `bun run format:check` | Check formatting without writing                              |

### Code Style & Git Hooks

- **Formatter:** Prettier 3 (`prettier --write .`) with `.prettierrc.json` (`printWidth: 100, singleQuote, semi, 2 spaces`) and `.prettierignore` (ignores `wrangler.*.jsonc`, lockfiles, `dist`, `.env`).
- **Git Hooks:** `simple-git-hooks` + `lint-staged` (auto-installed via `prepare`):
  - `pre-commit`: `lint-staged` → `prettier --write` for `*.{js,ts,json,css,md}`
  - `pre-push`: `bun run check && bun run build` (typecheck + config generation must pass)
- **Usage:**
  ```bash
  bun run format              # manual format
  bun run format:check        # CI check
  # hooks run automatically on `git commit` / `git push`
  # skip if needed: SKIP_SIMPLE_GIT_HOOKS=1 git commit -m "..."
  ```

### Build Optimization

- The Worker is bundled by `wrangler deploy` (esbuild minify) — no separate frontend build step.
- `bun run cf:config` is invoked automatically before `dev`/`deploy`/`build`.
- Observability (logs + Workers Analytics) is enabled in `wrangler.template.jsonc`.

## 📡 API Overview

All endpoints are under `/api`. `/api/sub` requires a valid `?token=<SUB_TOKEN>`.

| Endpoint         | Method | Auth          | Description                                             |
| ---------------- | ------ | ------------- | ------------------------------------------------------- |
| `/api/sub`       | GET    | `token` query | Generate subscription output (v2ray / clash / singbox). |
| `/api/proxies`   | GET    | —             | Paginated proxy list (search, country, port filters).   |
| `/api/countries` | GET    | —             | Country list with proxy counts from KV source.          |
| `/api/myip`      | GET    | —             | Returns client IP and Cloudflare colo data.             |
| `/api/check`     | GET    | —             | Latency probe for an allowlisted proxy target.          |

#### Example — Subscription

```bash
# Default: VLESS, clash format, cdn mode, wildcard, port 443, cc ID,SG
curl "https://yuliana.my.id/api/sub?token=<SUB_TOKEN>"

# Non-wildcard SNI mode, port 80
curl "https://yuliana.my.id/api/sub?token=<SUB_TOKEN>&mode=sni&wildcard=no&domain=support.zoom.us&port=80"
```

The `mode` (`sni` / `cdn`) and `wildcard` (`yes` / `no`) params select the `server`, `servername` (SNI), and `host` (WS Host header):

| Mode  | Wildcard | server              | servername          | host                |
| ----- | -------- | ------------------- | ------------------- | ------------------- |
| `sni` | `no`     | request host        | domain              | domain              |
| `sni` | `yes`    | domain.request-host | domain              | domain              |
| `cdn` | `no`     | domain              | request host        | request host        |
| `cdn` | `yes`    | domain              | domain.request-host | domain.request-host |

#### Credentials (derived from `SUB_TOKEN`)

Relay only accepts connections with credentials derived deterministically from `SUB_TOKEN` (a Cloudflare Worker secret — never hard-coded):

- **VLESS:** UUID = first 16 bytes of `SHA-256(SUB_TOKEN)` with UUID v4 bits set.
- The `/api/sub` link always uses the derived UUID; the raw token never appears in output.

Generate a strong token once: `openssl rand -base64 48`.

> ⚠️ **Security:** set `SUB_TOKEN` via `wrangler secret put SUB_TOKEN` (local) or the GitHub Secret `SUB_TOKEN` (CI). Never commit it.

## 🔒 Security Notes

- `/api/check` only accepts allowlisted proxy targets; rate-limited.
- Relays only accept credentials derived from `SUB_TOKEN`.
- HTTP redirects to HTTPS for non-local requests.
- WebSocket relay uses country bucket or direct proxy target path.
- CORS is permissive for the Worker deployment flow.
